**Linux** — `refryt-0.1.13-x86_64.AppImage`: download, `chmod +x`, run. Or use
`scripts/appimage-install.sh install` from source for a desktop launcher entry.

**Linux, Flatpak** — `refryt-0.1.13-x86_64.flatpak`. It isn't on Flathub, so install the file:
`flatpak install --user refryt-0.1.13-x86_64.flatpak`, then `flatpak run io.github.gridoe.refryt`.
It needs the GNOME 49 runtime, which Flatpak offers to fetch the first time. mpv and yt-dlp are
inside. The sandbox can't see your browsers' profile folders, so "Import from a browser" is hidden
and you sign in through the app's own window; "Launch on startup" is hidden too, since a sandboxed
app can't write a login item.

**Windows** — three options for x64, and two for ARM, cross-compiled from Linux with limited testing on real Windows
hardware:
- `refryt-0.1.13-windows-x86_64-setup.exe` — a real installer (Program Files, Start Menu,
  uninstaller). Unsigned, so SmartScreen will warn on first run — expected, not a bug.
- `refryt-0.1.13-windows-x86_64.msi` — the same files as an MSI, for deployment tools or a
  silent install (`msiexec /i refryt-0.1.13-windows-x86_64.msi /qn`). It installs to the same
  folder as the setup, so use one or the other.
- `refryt-0.1.13-windows-x86_64.zip` — portable, no install: unzip and run `refryt.exe`.
  Extract the whole folder before running; the exe needs the DLLs beside it.
- `refryt-0.1.13-windows-arm64.msi` / `.zip` — a native build for Windows on ARM, not yet tested
  on ARM hardware. The x64 files also run there under emulation.

**macOS** — `refryt-0.1.13-macos-arm64.dmg`, for Apple Silicon only. Open it and drag
Refryt to Applications. It is signed ad hoc and not notarized, so
macOS will refuse to open it on the first launch. Run `xattr -cr /Applications/Refryt.app` once,
or allow it in System Settings → Privacy & Security. libmpv and yt-dlp are bundled; nothing needs
installing.

Checksums for every file are in `refryt-0.1.13-SHA256SUMS.txt`.

What changed since 0.1.12:
- **Updates from inside the app** — refryt looks for a new release on GitHub when it starts
  ("Check for updates" in Settings → About turns it off). The Windows setup and MSI installs and
  the AppImage update and restart in place; the Flatpak, the AUR package and macOS say a new
  version is out and link its release page. "Later" keeps the notice away for a day. Thanks to
  @TZANTOU. (#5, #7)
- **Keep the songs you jump over** — a new option in Settings → Playback → Queue and history. With
  it on, playing a song further down Up next plays it now and keeps the songs that were before it
  as the next ones, in their order. Off by default, which skips them as before.
- **Linux tray** — a left click on the tray icon shows and hides the window, and hovering shows
  its name. On KDE Plasma's Wayland session, hiding to the tray now takes the window off the
  taskbar, and the tray icon brings it back in front. The Flatpak can't do that part: there the
  window still minimises to the taskbar.
- **macOS** — the window's traffic lights sit over the sidebar, as in other Mac apps (thanks to
  @hanandewa5, #8), and there is a menu bar with Playback, View, Window and Help menus. A window
  minimised from the app's own button no longer freezes once it is restored, and the app keeps
  its own icon in the Dock while it runs.
- **Fewer sign-in refreshes** — an empty section in the Library or History was taken for an
  expired sign-in, so an account with one renewed its sign-in on every launch. (#4)
