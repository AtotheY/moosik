# Moosik 0.1.17

Resume playback when a media-key fallback launches Moosik.

## Fixed

- Added an explicit `--resume` launch command for macOS and Linux. Fallback launchers can now start the saved song instead of only opening a paused player.
- When Moosik is already open, the command resumes its existing player without bringing the window forward or leaving a second player running.
- Repeated resume requests keep music playing instead of toggling it back to paused.
- Improved delivery of launch requests while the app is starting and when socket messages arrive in fragments.

Normal Play/Pause controls continue to use the operating system's active player. Ordinary app launches still restore the queue paused. This release does not automatically install a system-wide media-key helper or change keyboard bindings; an existing fallback launcher must invoke `--resume`. See [media controls](https://github.com/AtotheY/moosik/blob/moosik-v0.1.17/docs/media-controls.md).

## Update or install

Use **Moosik → Check for Updates…** to install and restart, or download the Apple Silicon DMG for a first installation. The update archive is signed with Moosik's Ed25519 key and the app uses the existing pinned release certificate.

The app is self-signed and not Apple-notarized. macOS may request Keychain approval again for the saved session after this update. Keep credentials in Keychain; there is no need to grant every app access.
